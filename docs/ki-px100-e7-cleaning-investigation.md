# KI-PX100 的 E7 与主动清扫协议调查

核对日期：2026-10-20。实机型号 `KIPX100`，固件 `SHARP_A04`。

## 结论

已接通本机局域网 ECHONET Lite 接口并读取属性表及私有状态。现有集成、两个上游主分支、当前夏普官方 Web 前端、ECHONET 标准及所查公开本地实现中，**均没有找到已确认的“立即执行预滤网机械清扫”命令**。

这表示目前无法可靠实现 HA 清扫按钮，不表示固件一定没有隐藏的维修命令。没有向设备发送任何 Set 请求，也没有尝试把清扫中的状态值写回设备。

## E7 的含义与本机操作限制

[KI-PX100 专属故障导航](https://cs.sharp.co.jp/trouble_check/div/air_purifier/navi_kipx100/ki_diag04_01_2.html)将 E7 定义为预滤网自动清扫未正常运行，首先要求重新安装预滤网、集尘盒及清扫刷。它不是“电机已损坏”的专属诊断。

[KI-PX100 官方说明书](https://jp.sharp/support/air_purifier/doc/kipx100_mn.pdf)中：

- 第 19、40 页：前次清扫后累计运行约 48 小时，且环境明亮、空气清洁、10 分钟没有按键操作时启动，正常约 7 分钟。48 小时指累计运行时间。
- 第 25 页：仅提供自动清扫 ON/OFF 设置；关闭后仍会在累计约 720 小时清扫一次。全文没有找到本型号公开的立即清扫步骤。
- 第 33 页：拆装维护应先停止运行并拔掉插头。
- 第 19、40 页：拆后盖会停止清扫；中途按停止可能让卷帘暂时不回位。不要绕过后盖联锁来试电机。

其他型号的“手动清扫”步骤不能直接套用。例如 [FAQ 158496](https://cs.sharp.co.jp/faq/qa?qid=158496)的适用机型只有 FP-140EX / FP-140EX-W。

## 云端与代码检查

核对了本仓库控制构造器、原始项目 `hldh214/cocoro-air` 的 `b31e2168dd265bad297b641861ddf03938041dc5`、直接父项目 `yuyuvn/cocoro-air` 的 `078cdea858e4f1008b2dc047383e5f5a4c49f78c`；调查时它们仍是远端主分支最新提交。

当前[官方 Web 页面](https://cocoroplusapp.jp.sharp/air)加载的脚本是 [`app.f722ed4d.chunk.js`](https://cocoroplusapp.jp.sharp/air/static/js/app.f722ed4d.chunk.js)，UTF-8 内容 SHA256 为 `9ece5660757833ce14ce2e6606fc5d07737c079d91ae12909e496f1d1e9b6f3f`。模式命令构造函数 `VI()` 没有构造预滤网清扫命令。

| 字段或功能 | 已确认含义 | 能否用作预滤网清扫触发 |
| --- | --- | --- |
| `k3.s1=0E` | 停机时预滤网清扫中的状态 | 未确认可写 |
| `k3.s1=1E` | 运行时预滤网清扫中的状态 | 未确认可写 |
| `k3.s1=60` | 房间清扫辅助模式 | 不等于预滤网清扫 |
| `k3.s1=0D` | 加湿内部洗净中的状态 | 不属于本机预滤网机构 |
| 上游 `maintain_supply` 的 `clean` | 记录维护日期，部分型号复位维护计数 | 不启动预滤网清扫 |
| `k3.s4` 耗材操作 | 更换或维护计数复位 | 没有机械清扫启动的依据 |
| `k3.s12=0000` | 用于切换或应用 AI AUTO 自定义模式 | 不属于机械清扫 |

官方 Web 对 dustbox 维护分支没有生成设备控制命令。云接口的 `opc=k3` 是云端 JSON 字段，不是可直接发送到 UDP 的完整 ECHONET 帧。

## 实机局域网调查

从 HA 所在网络发送标准 Get 请求，设备回应节点实例列表 `013501`，产品代码 `KIPX100`、厂商代码 `000005`。通信使用 UDP 3610，设备向 3610 端口回复；仅监听临时源端口可能收不到结果。

实机公布的属性表：

- Get：`80 81 82 84 85 86 88 89 8A 8B 8C 9D 9E 9F A0 C0 F0 F1 F2 F3 F4 FC FD`。
- Set：`80 81 A0 F3 F4`。这只能证明设备声明这些属性可写，不能证明任何猜测的字段值有效。
- 通知：`80 81 86 88 89 A0 C0 F3`。

读取结果：

| 属性 | 本次结果 | 解释范围 |
| --- | --- | --- |
| `80` | `30` | 电源开启 |
| `A0` | `41` | 自动风量 |
| `86` | `080000050100000000000000` | 厂商异常信息；见下方限制 |
| `88` | `42` | 标准异常发生状态没有报整体异常 |
| `F1/F2/F3` | 分别返回 40 / 40 / 27 字节 | 与云端温湿度、运行时长、维护标记和模式对应；没有发现清扫剩余计时字段 |
| `F3` | 模式字节为 `30` | 当前仍在飞沫粒子运行模式，并非清扫中 |
| `F4` | 94 字节全 `00` | 未找到公开的净化器字段定义，无法据此构造命令 |
| `F0/FC/FD` | 可读的私有数据 | 不推定其计时或控制含义 |

`86` 相比此前正常快照 `080000050000000000000000`，第五字节从 `00` 变为 `01`；云端与局域网读回一致。官方前端仅解释此区域中的部分其他位，没有解释这一个位，因此这里只保存与本次 E7 的相关性，**没有把它直接命名为 E7 传感器**。

另检查了目标设备常见 TCP 端口 22、23、80、443、1883、5000、8000、8080、8883，未发现可连接端口；不代表排除了全部厂商接口。

[ECHONET 规范 Release R rev.4](https://echonet.jp/wp/wp-content/uploads/pdf/General/Standard/Release/Release_R/Appendix_Release_R_r4.pdf)第 3.2.4 节（文档页 3-98）的空气清净器类没有自动扫尘触发属性。换滤提醒 `E1` 只能读取，不能当作清扫命令。

[sharp-echonet 原始实现](https://github.com/sohsatoh/sharp-echonet)确认了另一型号 KI-UX75 的私有状态和固定回复端口，但未提供预滤网清扫命令，其偏移也不能直接套用到 KI-PX100。

## 后续如何验证

优先按本型号官方排查步骤，在断电状态重新安装预滤网、集尘盒和刷子；这一步能排除官方列出的装配问题，仍不能单凭 E7 区分电机、机构或检测部件。

要实现无需等 48 小时的重复测试，下一步需要取得**适用于 KI-PX100 的维修试机步骤、厂商私有命令定义，或固件中相应处理逻辑**。只有可写属性表和全零读值不足以推导命令。尤其不应穷举 `F3/F4`、修改未知计数器，或把 `0E/1E` 当作控制值。

仓库提供独立的标准库只读工具 [`scripts/echonet_inspect.py`](../scripts/echonet_inspect.py)，用于重新发现设备、读取属性表及原始状态，不会修改设备，也不需要夏普账户。运行方法见脚本 `--help`。HA 集成的运行逻辑和实体在本次调查中没有修改。

```sh
python scripts/echonet_inspect.py --discover --interface <本机局域网IPv4>
python scripts/echonet_inspect.py --host <设备IPv4> --interface <本机局域网IPv4>
```

本次 7 项离线协议测试通过，Windows 发现设备及 HA 上完整属性读取均成功。工具与本报告已同步到 HA 的 `/config/cocoro_air_diagnostics/`，文件 SHA256 与仓库一致；现场只读快照保存在该目录的 `snapshot-e7-20261020.json`。局域网地址等现场信息不提交到公共仓库。
